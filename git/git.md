
# Git

## 1. GUI와 CLI

### 1. GUI(Grphic User Intteface)
- 그래픽을 사용해서 컴퓨터에 명령을 내림
- 일반적으로 PC를 조작하는 방식, 눈으로 버튼을 보고 커서로 클릭해서 명령을 내림

### 2. CLI(command Line interface)
- 명령어를 직접 타이핑
- 검은 화면에 커멘드 키를 타이핑, 터미널과 명령 프롬포트를 사용
- 키보드만으로 작업을 빠르고 수월하게 진행 가능, 그래픽 화면에 보이지 않는 숨겨진 기능 제어 가능
- 단순한 반복 작업을 명령어로 자동화 가능, 서버, 클라우드 개발 등 그래픽이 없는 환경에서 필수적인 도구

### 3. 기본 명령어
- `touch` – 파일 생성 / `mkdir` – 폴더 생성 / `ls` – 현재 위치의 폴더, 파일 목록 확인 /
- `cd` – 위치 이동 / `start` – 폴더, 파일을 열기 / `rm` – 파일 삭제 / `rm -r` – 폴더 삭제
- `pwd` – 현재 위치의 절대 경로 출력 / `cd ..` - 상위 폴더로 이동

### 4. 위치 파악 – 어느 위치에서 작업할지가 중요
- 절대 경로 – `pwd`로 정확한 위치를 찾은 후 한 번에 이동 – 정확한 좌푯값
- 상대 경로 – 현재 위치에서 위로(`cd ..`) 또는 아래로 (`cd 폴더명`) 이동

## 2. Git

### 1. Git이란? - 분산 버전 관리 시스템
- 분산 – 여러 개의 복제된 저장소에 저장
  - 반대 개념은 중앙 집중식 – 중앙 서버 하나로 모든 것을 관리
  - 인터넷에 연결하지 않아도 변경 이력과 코드를 로컬 저장소에 기록한 후, 추후에 동기화 가능
  - 중앙 서버에 의존하지 않고도 동시에 다양한 작업 가능
  - 중앙 서버의 장애나 손실에도 복구가 용이
- 버전 관리 – 히스토리를 관리하고 개발 되어온 과정을 파악, 이전 버전과의 변경 사항 비교 가능
- Git은 – 코드의 변경 이력을 기록하고 협업을 원활하게 해주는 도구

### 2. Git의 3가지 영역
- Working Directory – 실제 작업 중인 파일들이 위치하는 영역, 작업 중인 내 컴퓨터, 로컬
- Staging Area – 저장하기 전 업데이트 할 파일들을 선택해서 추가하거나 제외할 수 있는 임시 저장소, 가상 공간, CLI로만 확인 가능
- Repository – 파일이 영구적으로 저장되는 영역, 모든 버전과 업데이트 내역이 기록됨

## 3. Git 추가하기

### 1. 추가하기
- `git init` – 해당 폴더를 git으로 관리하기 시작, 로컬 저장소 열기
- `git add` – 변경 사항이 있는 파일을 로컬에서 staging area에 업로드
- `git commit` – 현재 staging area에 있는 파일들을 저장소에 저장, 변경 이력 남기고 메모
- `git config` – 사용자 정보 등록 (`git config --global user.email(이메일)` / `user.name(닉네임)`)
- `git status` – 로컬 저장소와 staging aread의 상태 확인
- `git log` – commit 기록 확인, commit id 확인 / `git log --oneline` – 간단히 보기

## 4. Git 수정하기

### 2. 삭제하기(Revert)
- `git revert <commit id>` - 해당 커밋 삭제, vim 편집기가 열리면 i를 눌러 입력 활성화 후 해당 커밋이 삭제된 결과를 기록하기 위한 커밋 작성, esc를 누르고 :wq로 저장하고 나감
- `git revert --on-edit <commit id>` - vim 편집기를 열지 않음
- `git revert --no-commit <commit id>` - 커밋은 하지 않고 staging area에 올림, 여러 커밋을 묶는 것 가능

### 3. 커밋 되돌리기(Reset)
- `git reset <commit id>` - 특정 커밋으로 되돌아간 후 그 이후의 커밋은 모두 삭제
- `--soft` – 되돌리기로 삭제된 커밋들을 로컬 서버와 staging area에 남김 – 언제든 불러오기 가능
- `--mixed` – 기록을 로컬 서버에 남김, 기본값
- `--hard` – 기록을 남기지 않음
- remote로 원격 저장소에 올라간 파일은 reset할 수 없음

### 4. 커밋 수정하기(amend)
- `git commit --amend` – vim 에디터가 열리며 수정 가능 
  - 바로 직전 생성한 커밋 삭제 – 커밋 오타 수정, 빠트린 내용 추가 등
  - 빠진 파일이 있다면 add 후 amend실행 – vim 에디터에 새로운 내용 추가 확인 후 닫기

### 5. 되돌리기(Restore)
- `git restore <파일이름>` - 한 번 커밋 한 파일을 수정, 저장한 후, 수정 전으로 되돌리기
  - 사실상 단순히 로컬에서 저장한 내용을 저장 전으로 돌리는 작업
  - 덮어쓰는 원리이기 때문에 복원은 불가능
- `git restore --staged <파일이름>` - add까지 한 상태에서 직전 commit으로 되돌리기
  - 이전 커밋이 없다면 되돌리기 불가능
- `git rm --cached <파일이름>` - add 또는 커밋까지 된 파일을 staging area에서 제거
  - unstaging / git에서만 제거, add 취소, 로컬에는 그대로 남아있음

### 6. 삭제한 커밋 복구하기
- `git reflog` – hard 옵션으로 지웠던 커밋까지 복구 가능

## 5. Git 원격 저장

### 1. 원격 저장소란? 
- 코드 버전 관리 이력을 온라인 상의 특정 위치에 저장하여, 여러 개발자가 협업하고 코드를 공유할 수 있는 저장 공간
- 온라인 상의 git 저장소 
 - git hub / git lab / bit bucket 등

### 2. 원격 연결 (Remote)
- 원격 저장소(깃허브)와 로컬 컴퓨터를 이어주는 행위
- `git remote add <저장소 별칭> <리모트 할 저장소 주소>` 
  - <주소>를 <별칭>이라는 이름으로 내 컴퓨터에 원격 저장소로 추가한다 
  - 저장소 별칭은 기본이 origin / 브랜치 이름은 기본이 master
- `git remote -v` - 원격 저장소 목록 확인
- `git remote rm <저장소 별칭>` - 원격 저장소 삭제

### 3. 업로드
- coomit까지 완료되어 로컬 레포즈토리에 저장되어 있는 자료를 원격 저장소로 이동하는 것
- `git push <저장소 별칭> <브랜치 이름>` - <별칭>에 <브랜치 이름>버전의 파일을 업로드 한다
- 첫 push에는 인터넷으로 접속해 git hub에서 인증을 받아야 함

### 4. 다운로드
- `git clone <저장소 주소>` - 해당 주소에 있는 파일들을 전체 복사
- `git pull <저장소 별칭> <브랜치 이름>` - 해당 저장소, 해당 브랜치의 수정 사항만 업데이트 함

## 6. 무시하기(ignore)

### 1. gitignore란? 
- git에서 특정 파일이나 폴더를 추적하지 않도록 설정
  - .gitignore라는 이름의 파일을 생성 - 앞에 닷(.) 중요, 확장자 없음
  - 파일을 열고 추적을 원하지 않는 파일, 폴더 명을 입력, 저장
  - git을 실행
- 이미 git의 관리를 받은 적 있는 파일이나 폴더에는 사용할 수 없음
  - cached 명령어로 git 캐시에서 삭제 후 재실행
